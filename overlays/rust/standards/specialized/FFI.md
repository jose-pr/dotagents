# Standard: C ABI and foreign bindings

Specialized standard: applies to a crate that exports `extern "C"` functions,
ships a C header, imports a C library, or is driven by bindings written in
another language. Adds to the base standards, above all
[UNSAFE.md](../base/UNSAFE.md); index: [README.md](../README.md). The bugs
that taught these rules are told in `../../kb/RUST.md`, "FFI".

## Where it lives

- **The `extern "C"` surface is one module of its own** (`exports/`, one file
  per subject), and the declarations of an imported library are another
  (`sys` or `raw`), generated by `bindgen` or a build step, never copied by
  hand. Both are on the `unsafe` allow-list; nothing else is.
- **A crate cannot both define a symbol and import it from a DLL.** A Rust
  wrapper over a library's ABI is its own crate, declarations only.
- **Every exported symbol carries the crate's prefix**: `<crate>_<subject>_<verb>`.

## The header

- **The header is generated from the Rust** (`cbindgen`) behind an optional
  `c-header` feature that makes cbindgen an optional build-dependency, so a
  default build compiles no code generator. (**house**)
- **The header is committed**, so a C consumer reads it without a Rust
  toolchain, and **a test compares the committed copy with a fresh render**.
  `build.rs` writes into the source tree only with `<CRATE>_WRITE_HEADER=1`.
- **A dependent crate finds it through Cargo**: `links = "<crate>"` and
  `cargo::metadata=include=<dir>` in `build.rs`, read downstream as
  `DEP_<CRATE>_INCLUDE`.
- **The header compiles as C and as C++**, checked by a test that runs a real
  compiler over it; generated declaration order is not trusted.
- A doc comment on an exported item lands in the header: changing it is
  regenerating the header.

## Types that cross

- **`#[repr(C)]` only on types that cross.** A Rust-only wrapper has none; the
  attribute promises a layout contract.
- **Layout is pinned** by `const _: () = assert!(size_of::<T>() == N &&
  offset_of!(T, f) == M);` for every crossing struct.
- **An enum crosses as an integer** (`u32`), converted on the Rust side with
  `TryFrom<u32>` that maps unknown values to an error or a catch-all. A Rust
  `enum` is never the type of a slot, field or return value a foreign side
  writes: a value outside its variants is undefined behaviour, and a C
  header that `typedef`s the enum as an integer invites exactly that.
- **Nullability is in the type**: `NonNull<T>` for never-null,
  `Option<NonNull<T>>` for may-be-null; both are `T*` in C.
- **Borrowed and owned are different types.** A getter's `const char*` is
  `&str` tied to `&self`; a builder's `char*` the caller frees is `String`.
  A borrowed handle is a separate type with no `Drop`, built by a struct
  literal, never by casting a pointer to `&Wrapper`.
- **Strings cross as pointer and length**, never NUL-terminated by
  assumption; text is checked as UTF-8 where it enters.

## Versioning a struct

- **A struct the other side may be older than leads with `struct_size`**, has
  a frozen floor, and grows only by appending. Each appended field is read
  only when `struct_size >= offset_of!(T, field) + size_of::<FieldType>()`;
  a missing one reads as absent.
- **An array of versioned structs carries its own stride**; `struct_size` of
  the first element cannot version an array.
- **Fields of a foreign struct are read by raw projection under its declared
  size**; a reference to the whole struct is formed only after the size
  check proves it whole.
- **Appending keeps binary compatibility, not source compatibility**: a Rust
  struct literal is exhaustive, so in-tree consumers must name the new
  field. Offer a constructor or builder so they need not.
- **Compatibility is demonstrated by loading an actually old binary**, built
  from the older source and kept as a test fixture, never by reasoning about
  a recompiled tree.

## Every exported function

- **Null-checks each pointer it dereferences**, and only where null is
  possible; a pointer documented never-null is `debug_assert!`ed.
- **Runs its body under `catch_unwind`** and returns a status on panic,
  forgetting the payload (dropping it can panic again). No panic crosses the
  boundary, including from `Drop` in a destroy function.
- **Writes its out-parameter first**, to the documented empty value, so a
  caller that frees `out` after a failure frees nothing. The same rule in
  every crate of the project.
- **Returns a status from one documented table**, shared by every header of
  the project, with `0` success and room for a host's own codes.
- **Refuses aliasing it cannot survive**: an `out` that is also an input is
  an error, not a silent overwrite.
- **Bounds every walk over foreign data**: iterative, or recursive with a
  depth limit that is itself exported (`<CRATE>_MAX_DEPTH`).
- **Never sizes an allocation from a foreign count** before reading the
  elements.

## Memory across the boundary

- **Whoever allocates names who frees.** A tree that can be freed on either
  side carries its allocator with it (a function table in the tree), and the
  free goes through that allocator.
- **Literal data in read-only memory** is either never freed by the library or
  freed without writing to it; the header says which.

## Linking

- **A binary links each exported symbol once.** Two crates that both define
  the same entry symbol fail to link (`LNK2005`/`LNK1169` on MSVC, "multiple
  definition" with GNU ld) or, if one crate's object is never referenced,
  one wins silently.
- **On Windows, an rlib plus the import library of a DLL that exports the same
  symbols is `LNK2005`.** A Rust crate that both uses the rlib and calls into
  such a DLL imports its own symbols with `#[link(kind = "raw-dylib")]` and
  links no import library.
- **After touching an exported symbol, build every profile a test can load**
  (`debug` and `release`): which one a test loads is decided by the search
  path, not by how the test was built.

## Bindings in other languages

- **A binding is a pure consumer of the C ABI**: it bundles no native build,
  names no Rust, and finds the library through `<PROJECT>_LIBRARY` or an
  explicit setter. (**house**)
- **It frees what it allocates on every path**, including a conversion that
  fails half way; a test with a counting allocator proves it.
- **Every type in its public signatures is exported** from its public entry
  point.
- **It states where it cannot run** (a browser, a 32-bit target, a platform
  without dynamic loading) in its README, beside the platforms it supports.
- **Status codes are one table**, checked against the header by a test.
